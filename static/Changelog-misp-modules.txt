Fix
~~~
- [csvimport] parse custom delimiters with csv, tolerate empty cells,
  import attribute_tag. [Andrei Bacescu]

  With a special delimiter, every line was first split on commas by
  csv.reader and only the first piece was split on the delimiter, so a
  comma inside a field truncated the rest of the line (a comment lost
  everything after its first comma, a line with a comma in its first
  field was dropped). Single-character delimiters now go through
  csv.reader with that delimiter, which also honours CSV quoting; longer
  delimiters split the raw lines and skip blank ones.

  An empty to_ids or category cell raised KeyError and aborted the whole
  import. These cells are now left unset, as for other empty fields.

  With a header of MISP attribute field names, the attribute_tag column
  was never turned into tags because the code looked for a Tag key, which
  header validation never accepts. Read attribute_tag instead.
- [defender_endpoint_export] match sha256 values against
  InitiatingProcessSHA256. [Andrei Bacescu]

  The sha256 query compared the value with InitiatingProcessSHA1, which
  holds SHA-1 hashes and can never equal a SHA-256 value, so matches on
  the initiating process image were missed. Use InitiatingProcessSHA256,
  the matching column in the advanced hunting schema.

v3.0.13 (2026-10-19)
--------------------

Changes
~~~~~~~
- [rdap] look hostnames up at their registered domain. [Claude Opus 5.5
  (1M context), Sami Mokaddem]

  Registries only hold registered domains, so asking rdap.org for a
  hostname, a subdomain or the host of a URL returned no record. The
  module now finds the registered domain with the ICANN section of the
  Public Suffix List and asks for it once; a public suffix is asked as
  given. The private section is skipped on purpose: duckdns.org is
  registered under .org, and its registry answers for duckdns.org, not
  foo.duckdns.org.

  The whois object's domain is the lowercased name that was asked, not
  RDAP's ldhName, and a comment says when it is the registered domain of
  the input host. The host is not added as a second domain, so the record
  does not read as the subdomain's own registration. A 404 or 400 on a
  domain lookup is reported as no record found, naming both names when
  they differ. Input is trimmed, lowercased and stripped of a trailing
  dot. IP lookups are unchanged.

Fix
~~~
- [html_to_markdown] block unspecified, shared, ULA and link-local
  ranges. [Claude Opus 5 (1M context), elhoim]

  is_safe_url() still let http://0.0.0.0/ (reaches loopback on Linux),
  100.64.0.0/10 (carrier-grade NAT), [::], fc00::/7 and fe80::/10 through,
  because BLOCKED_RANGES only listed loopback, RFC 1918 and IPv4
  link-local. Add those ranges, including their IPv4-mapped forms via the
  existing normalisation, and cover them with literal and resolved-host
  tests.
- [reversedns] fix nameserver fallback when config is an empty dict.
  [Claude Opus 5, elhoim]

  The module only fell back to the documented Google public DNS address (8.8.8.8)
  when the "config" key was entirely absent from the request. When MISP sends
  "config": {} (config present but no nameserver set, which happens whenever the
  module is enabled without an explicit nameserver override), the else branch
  that sets the fallback never runs, and the resolver silently falls back to
  whatever nameservers are configured on the system running misp-modules instead
  of the documented default. Analysts get PTR lookups resolved through an
  unexpected resolver with no indication the documented fallback was skipped.

  Replaced the presence check with a single expression that reads the
  nameserver from config when present and non-empty, and otherwise uses
  8.8.8.8, matching the documented behavior in all cases.

  Verified with flake8 (clean) and the full test suite against a locally
  started misp-modules server: 161 passed, 4 skipped, 5 subtests passed.
- [export_mod/goamlexport] fix typo'd dict name in introspection()
  [Claude Opus 5, elhoim]

  introspection() builds its result in a dict named modulesetup, but the
  inputSource branch assigns into moduleSetup instead (wrong capitalization).
  This is currently latent because the preceding `inputSource` bare-name
  existence check already raises NameError and is caught, so the buggy line
  never executes today; but the moment a caller defines module-level
  inputSource, the function would raise NameError('moduleSetup is not
  defined') instead of returning the introspection dict with inputSource
  included, breaking module setup reporting for any export module relying on
  that field.

  Verified with flake8 (clean) and the full pytest suite against a live
  misp-modules server on port 6780: 161 passed, 4 skipped, 5 subtests passed,
  matching baseline.
- [pgp_keyserver] ignore non-critical extension packets. [Alexandre
  Dulaunoy]
- [pgp_keyserver] accept optional HKP index fields. [Alexandre Dulaunoy]
- [scanmalware] report a degraded CT answer instead of no results.
  [Jonas Lejon]

  /ct/dns sheds load under pressure and then answers 200 with
  degraded: true. The API documents that as "we could NOT look": an empty
  subdomain list is an absence of data, not a fact about the domain. The
  module read it as an answer, so a lookup that never happened came back
  as "No ScanMalware results for this attribute". It now adds a partial
  result note saying the data could not be read and to retry.
- [scanmalware] list only hosts a browser actually contacted. [Jonas
  Lejon]

  The /hosts endpoint's default sources are observed, scripts and stream.
  A stream host was never fetched: a third party asked about it and DNS
  confirms it exists. The module labelled every returned host "contacted
  by a browser during a scan", so for github.com 156 of the 174 hosts it
  added carried a false label. It now asks for sources=observed,scripts,
  the two runtime-observed sources, which is what the label and the module
  description say.
- [scanmalware] ignore a trailing dot on the scanned host too. [Jonas
  Lejon]

  _is_scan_of_host stripped a trailing dot from the attribute's host but
  not from the scanned URL's host, so a URL on example.com. never matched
  the host's own scan of https://example.com./ and the module reported no
  result. Both hosts are now normalized the same way.

  values in generated script. [Claude Opus 5, elhoim]

  The module builds a shell script that authenticates to and calls the Cisco
  fireSIGHT manager API, interpolating the module config (IP, login,
  password, domain/policy IDs) and attribute values (destination IPs, URLs,
  event info) directly into single-quoted shell strings. Any of those
  values containing a single quote breaks out of the quoting, so an
  attacker-controlled attribute value (e.g. an ip-dst or url attribute with
  a `'` in it) can inject arbitrary shell commands into the exported .sh
  file, which an analyst may run unmodified. Separately, `config` was only
  assigned inside `if "config" in request:` but read unconditionally right
  after, raising a NameError whenever the request carries no "config" key.

  Every value written into the generated script is now passed through
  shlex.quote(). For the JSON access-rule block, which embeds several
  attribute values inside one shell-quoted assignment, the JSON content is
  built as plain text first and the whole assembled string is shlex-quoted
  once, since quoting the individual sub-values would leave stray quote
  characters inside the outer quoted string. `config` is initialised to
  `{}` before the conditional assignment so referencing it never raises a
  NameError.

  Verified with flake8 (clean) and the full pytest suite against a live
  misp-modules server: 161 passed, 4 skipped, 5 subtests passed, matching
  the baseline.

- Fix six defects found auditing the module before merge. [Tolga SEZER]

  Every one of these produced a positive-looking answer for a question the module
  had not actually answered, which for a reputation module is the failure that
  matters most.

  An auth failure or a rate limit on the Edge fallback was accepted as the answer.
  The first lookup checked for the error marker, the second did not, so a rejected
  key or a 429 became "not in the malicious catalog and not analysed". The
  fallback doubles the request rate for every bare id, so a rate limit there is
  the expected case rather than a rare one. Both lookups now go through one path
  that propagates the failure.

  Host matching used str.endswith(), so evil-pypi.org matched pypi.org and a

  typosquat URL is exactly the indicator a MISP event holds. The boundary is now a

- [cof2misp] fix operator precedence in COF timestamp validation.
  [Claude Opus 5, elhoim]

  is_cof_valid_simple checked `not (A and B) or (C and D)`, which Python
  parses as `(not (A and B)) or (C and D)` rather than the intended
  `not ((A and B) or (C and D))`. As a result, a record carrying only the
  valid zone_time_first/zone_time_last pair (and no time_first/time_last)
  was rejected as invalid, since `not (A and B)` is already True in that
  case and short-circuits the OR to True, triggering the "missing
  mandatory fields" error and a False return even though the record is
  well-formed. A record with both pairs present was also flagged wrong
  for the same reason.

  Parenthesised the check as `not ((A and B) or (C and D))` so validation
  succeeds whenever either timestamp pair is present, matching the
  intended COF semantics.

  Verified with py_compile and the full pytest suite against a live
  modules server on port 6786: 161 passed, 4 skipped, 5 subtests passed,
  matching the documented baseline.
- [geoip_country] guard against malformed domain|ip composite value.
  [Claude Opus 5, elhoim]

  When handling a domain|ip composite attribute, the module split the value on
  "|" and unconditionally indexed the second element to extract the IP. A
  composite attribute lacking the separator, or otherwise malformed, raises an
  uncaught IndexError, which surfaces to the analyst as a raw traceback instead
  of a module error response.

  Verified by running flake8 (clean) and the full pytest suite against a live
  modules server on port 6776: 161 passed, 4 skipped, 5 subtests passed,
  matching the documented baseline.
- [passivetotal] recognise SHA1 hashes by their real length. [Claude
  Opus 5, elhoim]

  process_malware() classified hashes by length: 32 for MD5, 41 for SHA1,
  64 for SHA256. A hex-encoded SHA1 is 40 characters, not 41, so every SHA1
  returned by the malware endpoint fell through all three branches and was
  silently dropped. The sha1 attribute list therefore always came back empty,
  with nothing in the response to indicate that values had been discarded.

  Verified with the full test suite (161 passed, 4 skipped) against a locally
  running misp-modules server, plus flake8 on the changed file.

  Queries the public ScanMalware API for a domain, hostname, URL or IP attribute.
  No API key is required: the API is anonymous, and a key only raises the rate
  limit.

  Improving regex (validating e-mail)
- Improving regex (validating e-mail) [x41\x43]

  Line 48:
  The previous regex ` ^[\w\.\+\-]+\@[\w]+\.[a-z]{2,3}$ ` matched only a small subset of valid e-mail address (e.g.: didn't match domain names longer than 3 chars or user@this-domain.de or user@multiple.level.dom) and needed to be with start (^) and end ($).
  This ` [a-zA-Z0-9!#$%&'*+\/=?^_`{|}~-]+(?:\.[a-zA-Z0-9!#$%&'*+\/=?^_`{|}~-]+)*@(?:[a-zA-Z0-9](?:[a-zA-Z0-9-]*[a-zA-Z0-9])?\.)+[a-zA-Z0-9](?:[a-zA-Z0-9-]*[a-zA-Z0-9])? ` is not perfect (e.g: can't match oriental chars), but imho is much more complete.

  Regex tested with several e-mail addresses with Python 3.6.4 and Python 2.7.14 on Linux 4.14.

  Added support for malformed internationalized email headers
- Added support for malformed internationalized email headers. [seamus
  tuohy]

  When an emails contains headers that use Unicode without properly crafing
  them to comform to RFC-6323 the email import module would crash.
  (See issue #119 & issue #93)

  To address this I have added additional layers of encoding/decoding to
  any possibly internationalized email headers. This decodes properly
  formed and malformed UTF-8, UTF-16, and UTF-32 headers appropriately.
  When an unknown encoding is encountered it is returned as an 'encoded-word'
  per RFC2047.

  This commit also adds unit-tests that tests properly formed and malformed
  UTF-8, UTF-16, UTF-32, and CJK encoded strings in all header fields; UTF-8,
  UTF-16, and UTF-32 encoded message bodies; and emoji testing for headers
  and attachment file names.
